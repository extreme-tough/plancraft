# Celebration & Event Planner SaaS — Product Specification

## Product definition

Build a **Celebration and Event Planner SaaS** that helps a defined user persona plan and execute an event within their budget, preferences, timeline, and constraints. The goal is not an AI that merely suggests party ideas, but an AI that helps users **actually make the event happen**.

The target user is intentionally open-ended: it may be an individual/family organizer, community organizer, or event-management company. However, the product must solve a genuine problem for one clearly defined persona.

The SaaS should help users manage the connected moving parts of event planning: budget, guest list, venue, decoration, food, vendors, timeline, dependencies, and last-minute changes.

## Product principles

- Solve one real planning problem for one defined user.
- Treat event planning as a connected system, not isolated checklist items.
- Use GenAI only where it adds meaningful value.
- Keep the user in control; AI should ask, listen, and adapt.
- Be transparent about estimates, assumptions, and unverified vendor information.
- Design for change and plan revision.
- Focus on execution support, not inspiration alone.

## Core user journey

1. User selects or describes the event type and context.  
2. System asks practical onboarding questions.  
3. System generates a personalized starting plan.  
4. User refines priorities, budget, guests, theme, and requirements.  
5. System maintains a task timeline with dependencies and deadlines.  
6. User records vendor quotations and compares options.  
7. When constraints change, the system revises the plan and highlights affected decisions.

## Functional acceptance criteria — summary

The SaaS must support:

- Event creation with occasion, date, budget, guest count, and planning window.
- Practical onboarding questions before generating a plan.
- A personalized starting plan based on actual user inputs.
- Personalized recommendations based on preferences, audience, accessibility, culture, and venue constraints.
- Conversational refinement and alternative suggestions.
- Categorized budget planning and scenario comparison.
- Budget impact analysis when guest count, category allocation, or total budget changes.
- Trade-off recommendations instead of automatic cost cutting.
- Clear separation between estimated and confirmed costs.
- A prioritized, deadline-driven task timeline.
- Task dependencies and plan updates when tasks are completed or delayed.
- Plan revision when budget, date, guest count, or other constraints change.
- Vendor requirement definition, question preparation, quotation capture, and comparison.
- Transparent handling of unverified vendor availability and pricing.

## GenAI requirements

| ID | Acceptance criterion |
|---|---|
| AI-01 | The application must use GenAI to understand the user’s situation, priorities, and constraints before producing recommendations. |
| AI-02 | The application must use GenAI to personalize suggestions rather than return static event-planning templates. |
| AI-03 | The application must use GenAI to adapt the plan when user inputs or constraints change. |
| AI-04 | The application must use GenAI to convert natural-language requests into actionable plans. |
| AI-05 | The application must respond to the user’s actual inputs in real time; it must not rely on hardcoded or dummy data for GenAI-driven flows. |
| AI-06 | If a user enters an 8 lakh budget, the generated recommendations and allocations must be appropriate for an 8 lakh budget. |
| AI-07 | Dummy data may be used only for ML/model-training scenarios, not as the basis for real user-facing GenAI answers. |
| AI-08 | The application must be transparent about AI limitations, assumptions, estimates, and unverified information. |
| AI-09 | The application must keep the user in control of final decisions. |
| AI-10 | The application must avoid using AI where it does not solve a meaningful user problem. |

## UX and quality criteria

- Provide a clear, usable interface and coherent user flow.
- Define wireframes and user flow before implementation.
- Reflect deliberate human product decisions, not an entirely AI-generated product.
- Prioritize a real user problem over feature count.
- Build a web application; native Android or desktop apps are out of scope.

## MVP scope

Based on the guidance to start small, the strongest MVP should focus on **one persona and one execution problem**, rather than building a full marketplace, invitation system, guest manager, reminder engine, and theme generator at once.

### Recommended MVP

- **Persona:** A family planning a wedding or small celebration with a fixed budget.  
- **Core problem:** Turning an initial event idea into a realistic, revisable execution plan.  
- **Must-have modules:**
  - Onboarding questions
  - Personalized event plan
  - Categorized budget
  - Scenario comparison
  - Prioritized task timeline with dependencies
  - Plan revision on constraint change
  - Vendor-quotation comparison
- **AI role:**
  - Clarify needs
  - Personalize recommendations
  - Explain trade-offs
  - Adapt the plan
  - Convert natural-language requests into tasks
- **Explicit non-goals for MVP:**
  - Live vendor marketplace
  - Real-time vendor availability
  - Confirmed pricing
  - Invitations
  - Reminders
  - Guest RSVP management

These are non-goals unless they directly serve the selected persona’s core problem.

## Final acceptance test

A user creates an event, receives a budget and timeline, then returns with changed constraints—such as a lower budget and an event date moved earlier. The application must help them revise the plan; it must not force them to begin again.

**In one line:** Build an execution-oriented, transparent, personalized event-planning SaaS—not an AI idea generator.
